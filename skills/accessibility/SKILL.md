# Accessibility — usable by everyone

Accessibility means the software works for everyone, including people with disabilities — not just people using it in the "typical" way. Apply the guidance below when building or reviewing anything user-facing. Catch issues early; when unsure, follow the "Do" and avoid the "Don't".

**Do**
- Aim for WCAG 2.2 AA; check work against POUR (Perceivable, Operable, Understandable, Robust). WCAG is the main rulebook for accessible digital things — like a building code for websites and apps.
- Give meaningful images alt text (a short written description a screen reader can read aloud); write link text that names its destination.
- Keep text contrast at least 4.5:1 (a measure of how much text stands out from its background — higher is easier to read); ensure full keyboard access and a logical heading structure.
- Write error messages that state the problem and how to fix it.

**Avoid**
- Signaling meaning with color alone (e.g. errors shown only in red — add an icon or text too).
- Vague links ("click here"), missing alt text, keyboard traps (a spot where a keyboard-only user gets stuck), or auto-playing media.
